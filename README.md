# 知行财务 · 开票管理 MVP

供公司内部财务人员体验第一阶段流程的网页端原型，使用 Node.js 内置模块运行，无需安装第三方依赖。

## 启动

需要 Node.js 20 或更新版本。

```powershell
npm start
```

浏览器访问 [http://localhost:3000](http://localhost:3000)。如需更换端口，可设置环境变量 `PORT`。

初始测试账号：`admin` / `abc12345`。首次登录会要求修改密码。首次运行时，系统在 `data/store.json` 创建本地数据文件；删除该文件会清空测试数据，并在下次启动时重新初始化管理员。

## 已实现

- 管理员登录、密码哈希存储和首次登录改密。
- 管理员创建业务申请人、审批人和财务开票员账号；新账号首次登录需改密。
- 开票申请：购方名称及税号、票种、商品/服务、价税合计、税率和备注。
- 审批通过/退回、退回原因和流程记录。
- 财务登记已在合规开票平台开具的发票号码。
- 开票申请列表、发票台账、操作日志和统计概览。

## 建议测试路径

1. 使用初始管理员登录并修改密码。
2. 在「用户管理」创建一个业务申请人账号和一个财务开票员账号（初始密码至少 8 位）。
3. 退出管理员账号，以申请人登录并提交开票申请。
4. 退出并以财务开票员登录，审核申请；管理员和财务角色也可以登记开票结果。
5. 在「发票台账」查看记录，并检查工作台和报表汇总。

管理员兼有审批和开票登记权限，方便小团队直接走通流程。

## Netlify 临时公网演示

项目已适配 Netlify Functions 和 Netlify Database：静态网页由 Netlify 托管，API 在 Functions 运行，用户、申请和日志保存在 Postgres 中。部署前需要：

1. 将代码推送到你自己的 GitHub、GitLab 或 Bitbucket 仓库，再在 Netlify 导入该仓库。
2. 在 Netlify 为站点配置 `ADMIN_USERNAME=admin` 和 `ADMIN_PASSWORD`。生产密码至少 12 位；只在 Netlify 环境变量面板填写，不要提交到代码。
3. Netlify 首次部署会根据 `netlify/database/migrations` 创建数据库结构。用 Netlify 提供的 HTTPS 站点地址访问，管理员首次登录后需要修改密码。
4. 由管理员为每位演示客户创建单独的「业务申请人」账号。不要把管理员账号提供给客户；申请人只会看到本人提交的申请。

当前目录还没有 Git 仓库，且本机没有已登录的 Netlify CLI，因此还需完成 Netlify 账户授权并连接 Git 仓库，才能得到真实公网 URL。Netlify 免费计划是 300 credits/月硬上限；数据库计算、数据库带宽和生产部署会消耗额度，额度耗尽可能暂停服务。Netlify 文档说明免费档不自动追加扣费，但数据库存储在 2026-07-01 后的计费规则也应在创建数据库前于账户面板核对。Netlify 分配的 `netlify.app` 网址在中国大陆的访问质量需由目标客户网络实测。

这只是客户可操作的演示环境，不适合生产业务；请勿录入真实企业、购方或发票信息。系统不连接税务机关平台，也不生成法定发票文件。

## 当前范围说明

本 MVP 使用本地 JSON 文件保存数据，适合单机/临时演示，不适合多实例生产部署。生产启动时必须通过环境变量设置管理员初始密码，登录 Cookie 会要求 HTTPS；公开预览还有基础登录限流。系统不会连接税务机关平台、不会生成法定发票文件；财务应先通过已授权的合规平台实际开票，再将发票号码登记到系统。正式上线前应替换持久化存储、建立可靠备份与恢复、补充完整企业身份认证及税务接口，并由财务确认票种和税率规则。
